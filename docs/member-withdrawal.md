# 회원 탈퇴

`POST /api/users/me/withdrawals`는 현재 회원의 계정·인증 자료를 제거하고 공동 돌봄 기록을 보존한다. 요청자는 세션에서 결정하며 JSON으로 사용자 ID·소셜 식별자를 받지 않는다.

```json
{"clientRequestId":"b950288d-7f64-49e8-83e4-1cb5d9754579"}
```

세션 쿠키와 `X-CSRF-TOKEN`, `Content-Type: application/json`이 필요하다. `clientRequestId`는 필수 UUID이고 추가 필드는 허용하지 않는다. 기존 변경 API와 같은 1 MiB 요청 본문 제한을 적용한다. 성공은 본문 없는 `204`, `Cache-Control: no-store`, 현재 세션 쿠키 만료다.

## 처리와 보존

- 하나라도 소유 공간이 남으면 `409 OWNED_SPACE_REMAINS`다. 소유권 이전 또는 공간 전체 삭제를 먼저 완료해야 한다. `DELETING` 공간도 검사한다.
- 모든 현재 참여를 `WITHDRAWN`으로 종료하고 공간별 버전을 한 번 올린다. 미완료·표시 중인 담당 할 일을 미지정으로 전환하고 변경 이력을 추가한다. 완료된 할 일과 이전 문서는 보존한다. 본인 편집 잠금은 모두 해제한다.
- 현재·과거 참여의 `user_id` 연결을 제거한다. 공동 소식·근거·제안·확정 항목·변경 이력과 작성 당시 참여 ID는 유지한다. 공개 작성자/행위자 표현은 기존 `{membershipId:null, displayName:null, withdrawn:true}`를 사용한다. FE는 이를 ‘탈퇴한 작성자’로 표시한다. 내용 자체에 사용자가 입력한 개인정보까지 탐색·삭제하는 기능은 아니다.
- 대기 변경 요청은 현재 참여 검증에서 `REQUESTER_LEFT`로 무효화되며 이후 승인할 수 없다. 결정 완료 요청·공동 기록은 보존한다.
- 본인의 전역 명령 영수증과 계정·소셜 연결·전체 JDBC 세션/속성을 같은 DB 트랜잭션으로 제거한다. 다른 회원의 영수증·세션과 익명 로그인 준비 세션은 유지한다. 계정 삭제 실패 시 참여 종료·담당 해제도 전부 롤백한다.
- 커밋 후 현재 요청의 세션/보안 컨텍스트와 회원별 메모리 OAuth 인증 자료를 제거한다. Google/Kakao 제공자 자체의 연결 해제 API·외부 백업/로그 정리는 후속 운영 범위다.

## 반복 요청과 재가입

성공 후 이전 회원의 요청은 `401 UNAUTHENTICATED`다. 이 경로는 인증 검사를 CSRF보다 먼저 수행하므로 삭제된 세션 쿠키의 재요청도 401이다. 유효한 회원의 CSRF 누락은 403이다. 동일 처리 중인 요청은 `409 REQUEST_IN_PROGRESS`, 다른 명령에 이미 사용된 요청 ID는 `409 IDEMPOTENCY_KEY_REUSED`다. 탈퇴 성공 영수증이나 회원 복원용 tombstone은 남기지 않는다.

같은 소셜 계정으로 다시 로그인하면 새로운 회원 UUID를 발급한다. 기존 공간 참여·소유권·요청 권한을 복원하지 않으며, 새로운 초대를 통해 별도로 참여할 수 있다. FE는 성공 후 사용자/공간 캐시를 비우고 로그인 화면으로 이동해야 한다. FE 화면 연결은 이 백엔드 변경 범위에 포함하지 않는다.

## 동시 처리와 V22

탈퇴는 요청 ID 잠금 → 정렬된 제공자 식별자 잠금 → 회원 lifecycle advisory lock → UUID 순 공간 행 잠금을 사용한다. 회원 연결을 제거하기 전에 과거 참여 공간까지 잠가 작성자·권한 변경과 직렬화한다. 새 공간 생성·초대 참여는 회원 잠금 후 존재를 검사한다. 소유권 이전은 같은 공간 잠금과 현재 참여 조건을 재검사한다. OAuth 회원 조회·인증 자료 저장도 기존 회원 lifecycle을 확인한다. 제공자 HTTP 요청 중 DB 트랜잭션을 유지하지 않는다.

Flyway V22는 `spring_session.principal_name`의 서비스 UUID에서 `principal_user_id`를 생성하고 계정 FK에 `ON DELETE CASCADE`를 적용한다. 계정 삭제 시 모든 저장 세션과 속성이 함께 제거되고, 탈퇴 직전 시작한 로그인/요청의 지연 저장도 이전 UUID로 세션을 다시 만들 수 없다. 기존 유효 회원·익명/비회원 principal 세션은 유지하고, UUID principal의 기존 고아 세션은 정리한다. 운영 배포 시 이 마이그레이션은 기존 세션 테이블 잠금을 사용한다.

자동 검증은 Testcontainers PostgreSQL과 합성 계정·가짜 OAuth를 사용한다. 개발/운영 계정을 탈퇴시키거나 실제 제공자 연결을 해제하지 않는다.
