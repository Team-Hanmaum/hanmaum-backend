# 백엔드 아키텍처

Spring은 인증·권한, 원본과 확정 데이터, 변경 이력을 관리한다. FastAPI는 소식과 같은 공간의 후보를 받아 검토용 제안을 반환한다. 사용자 화면에는 BE의 공개 API를 제공한다.

## 도메인 패키지 구조

루트는 `com.hanmaum.backend`다. `controller`는 HTTP, `service`는 업무 규칙과 트랜잭션, `repository`는 저장과 조회를 담당한다. 하위 패키지는 실제 구현이 있을 때 만든다.

| 패키지 | 책임 |
| --- | --- |
| `auth`, `user` | 로그인·세션 API, 회원과 소셜 계정, 탈퇴 |
| `carespace` | 돌봄 공간, 초대, 참여·소유권 |
| `record`, `analysis` | 소식 원본, 분석 접수·상태·실행 |
| `ai`, `proposal` | 내부 AI 통신, 제안·변경 요청 검토와 결정 |
| `careitem`, `dashboard`, `sharing` | 돌봄 항목·근거·이력, 현황판, 공유 링크 |
| `global` | 보안, 오류·응답, 공통 설정과 OpenAPI |

## 공간 권한

- 현재 회원과 소셜 계정 연결을 검증하고, 공간에 대한 접근은 업무 처리 시점의 참여와 역할로 결정한다.
- 소유자는 최종 반영과 공간 관리를 담당한다. 구성원은 소식 작성·조회·초대·변경 요청을 할 수 있다. 본인 담당 할 일의 직접 등록·상태 변경, 본인 원본 삭제는 개별 정책을 적용한다.
- 공유 링크도 읽는 시점에 현재 참여를 확인한다. FE의 공유 진입·로그인 복귀·카카오 공유는 [공유 계약](share-links.md)을 참고한다.

### 돌봄 공간 생성·조회

공간과 최초 소유자 참여를 함께 저장한다. 일반 참여자는 현재 소속 공간만 조회한다. 초대는 발급 당시 참여와 유효 기간을 확인한다. 소유권 이전·나가기·내보내기는 같은 공간의 참여 변경을 직렬화한다. [공간·참여 API](api-conventions.md#돌봄-공간-api)

## 데이터 변경 원칙

- Flyway로 스키마를 관리하고 이미 적용된 SQL은 새 버전으로 보완한다.
- 변경은 권한·버전·잠금을 필요한 시점에 확인한다. 선택 묶음은 한 트랜잭션에서 반영한다.
- `clientRequestId`가 필요한 요청은 업무·대상·내용이 같은지 확인한다. 성공 기록에 원문을 복제하지 않는다.
- 원본 삭제는 관련 분석·제안·근거·문서 내용을 함께 정리한다. 재확인 대상은 확인될 때까지 현황판과 새 공유에서 제외한다. [소식 원본 삭제](api-conventions.md#소식-원본-삭제-api)

## 분석 실행과 제안 저장

1. 소식 원본과 최초 `QUEUED` 실행을 같은 트랜잭션에서 저장한다. 과거 분석 미접수 소식의 재전송은 `analysis: null`을 반환한다.
2. 워커가 실행을 점유하고 DB 트랜잭션 밖에서 AI에 요청한다.
3. 저장 전에 참여, 원본, 후보와 근거의 유효성을 재검사한다. 제안과 근거는 원자적으로 저장하며 확정 항목은 소유자 반영으로 변경한다.

## 운영 기준

Vercel FE와 Lightsail의 Nginx·BE·PostgreSQL·AI로 구성한다. BE와 AI는 내부 HTTPS로 통신한다. 최신 `dev`의 push CI 성공 후 자동 배포하며, 최신 `dev`의 수동 실행도 지원한다. 앱 교체 전에 DB 백업을 S3에서 확인한다. [배포 안내](deployment.md)
